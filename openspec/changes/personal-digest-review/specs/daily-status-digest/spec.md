# Spec Delta

## REMOVED Requirements

### Requirement: 摘要內容與長期缺席摺疊
**Reason**: 群組已合併到其他群組，系統僅剩單一使用者（柯啟鴻，M001）。「漏卡名單」「門檻風險名單」「長期缺席摺疊」「N 人完成·全月均 X%」等都是跨成員比較/彙總概念，單人情境下沒有意義（例如螢幕截圖顯示「1 人完成・全月均 36%」這種不自然的措辭）。
**Migration**: 由新需求「摘要內容與個人復盤呈現」取代，改為呈現使用者個人的今日打卡狀況與「跟自己過去比較」的分析（本月累計、連續打拳、今日 vs 上月同一天、今日 vs 歷史累積平均、追蹤軌道預估）。

### Requirement: 狀態變化事件判定
**Reason**: 此需求定義的「開始缺卡」「回歸」「跌破門檻」「回到門檻」「轉入長期缺席」等事件，其判定與呈現方式（比對前後兩日快照、產生事件清單）是為了在多成員情境下提醒管理員「誰的狀態變了」。單一使用者情境下，這類事件對使用者自己而言價值有限——使用者本人每天打卡，不需要系統告訴他「你今天開始缺卡了」這種事件化的提示，他直接從復盤內容的「今日打卡狀況」與各項比較數字就能判斷。
**Migration**: 不再於訊息中呈現事件清單。`buildDailySnapshot`/`diffStatusEvents` 的底層計算函式（`missed`/`miss_streak`/`passing` 等快照欄位計算）保留於程式碼中不變，僅訊息格式（`formatDigestMessage`）不再呼叫 `diffStatusEvents` 的輸出做為呈現依據。

### Requirement: 推播對象與投遞
**Reason**: 此需求描述的是「推播給多位已綁定 LINE 的管理員、個別失敗不影響其他收件人」的多收件人情境（`僅推播給已綁定的管理員`、`未綁定的管理員略過`、`單一收件人失敗不影響其他` 三個 scenario 皆以「多位管理員」為前提）。系統已在前次變更將收件人固定為柯啟鴻（M001）一人，不存在「多位收件人」的情境，這些 scenario 描述的行為已不成立。
**Migration**: 由新需求「單一使用者推播」取代，描述固定推播給 M001、失敗不影響快照寫入的行為。

## ADDED Requirements

### Requirement: 摘要內容與個人復盤呈現
系統僅剩單一使用者（柯啟鴻，M001）時，中午摘要 SHALL 呈現個人復盤格式：今日打卡狀況、本月累計、連續打拳天數、今日與上月同一天的對照、今日與歷史累積平均的對照、追蹤軌道預估。請假日 SHALL 以「今日已請假（事由）」呈現，MUST NOT 顯示為「今日未打卡」。

#### Scenario: 一般打卡日的復盤內容
- **WHEN** 柯啟鴻於剛截止的邏輯日完成 6 項任務（6.5 分），本月累計達成率 45%
- **THEN** 摘要顯示今日 8 項任務勾選狀態與 6.5 分、本月累計得分與 45% 達成率、距目標差、連續打拳天數、今日與上月同一天的達成率對照、今日與歷史累積平均的對照、追蹤軌道預估月底達成率

#### Scenario: 今日未打卡
- **WHEN** 柯啟鴻剛截止的邏輯日無打卡紀錄且未請假
- **THEN** 摘要明確標示「今日未打卡」，其餘本月累計、連續打拳、比較區塊照常呈現（反映實際現況，不因今日未打卡而省略）

#### Scenario: 今日請假
- **WHEN** 柯啟鴻剛截止的邏輯日已請假（事由「出差」）
- **THEN** 摘要顯示「今日已請假（出差）」，MUST NOT 顯示為「今日未打卡」

#### Scenario: 上月同一天無資料
- **WHEN** 柯啟鴻起算日晚於上月同一天（例如上月尚未加入），或上月同一天無打卡紀錄
- **THEN** 「今日 vs 上月同一天」區塊顯示「上月無資料」，不顯示誤導性的 0%

#### Scenario: 無歷史資料
- **WHEN** 柯啟鴻本月為第一個計分月，尚無任何歷史已結束月份的紀錄
- **THEN** 「今日 vs 歷史累積平均」區塊顯示「暫無歷史資料」

### Requirement: 單一使用者推播
系統僅推播給柯啟鴻（M001）本人，不再對多位管理員群發。推播 MUST 使用 `LINE_CHANNEL_ACCESS_TOKEN`（Messaging API channel）。既有的 `LINE_CHANNEL_ID` / `LINE_CHANNEL_SECRET` 屬 LINE Login channel，用途不同，MUST NOT 用於推播。

推播失敗 MUST NOT 使快照寫入失效；失敗 MUST 寫入 log。

#### Scenario: 僅推播給柯啟鴻
- **WHEN** 每日摘要產生完成
- **THEN** 僅對柯啟鴻（M001，已綁定 LINE）推播，不對其他帳號推播

#### Scenario: 推播失敗不影響快照
- **WHEN** 對柯啟鴻推播時 LINE API 回傳錯誤
- **THEN** 記錄錯誤並回傳失敗狀態，快照資料保持已寫入（供下次重跑補送）
